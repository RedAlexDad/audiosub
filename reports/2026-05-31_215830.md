# Report 2026-05-31 21:58 UTC

## What was added
- `src/logging.rs` — добавлен параметр `use_file_log: bool`. При `true`: файловое логирование через `tracing_subscriber::fmt().with_writer()` + panic hook в `/tmp/audiosub_stderr.log`. При `false`: поведение идентично старому (stderr).

## What was changed
- `src/audio/pulse.rs` — удалён `unsafe impl Send for PulseCapture {}` и `#[allow(unsafe_code)]`. `Simple` из `libpulse-simple-binding` уже реализует `Send` (upstream `unsafe impl Send for Simple`).
- `src/lib.rs` — удалён `#![allow(dead_code)]`. Проверено `cargo check --lib` — 0 warnings.
- `src/main.rs` — убраны `mod redirect_stderr`, вызов `redirect_stderr::StderrRedirect::new()`. `logging::init()` вызывается с флагом `use_file_log`.
- `src/redirect_stderr.rs` — удалён целиком (весь модуль на fd-ред. через libc dup/dup2).

## Problems encountered
- `tracing_subscriber::fmt().with_writer()` требует владения `File`, а не ссылки. Решение — `try_clone()` внутри замыкания, создающего новый `File`-дескриптор на каждый вызов writer.
- Panic hook тоже должен писать в тот же файл. Решение — клонировать `File` до установки hook-а.
- `cargo fmt` отверг длинную строку `.with_writer()` — потребовал разбить цепочку на несколько строк.

## How they were solved
- `try_clone()` возвращает новый `File` с тем же дескриптором — подходит для `with_writer()`.
- Panic hook использует тот же клон через `move`-замыкание.
- `cargo fmt` (`make verify` шаг 4) указал точный формат — применён.
